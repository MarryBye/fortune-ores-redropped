# Отчёт по доработке FortuneOres

Дата: 2026-07-24. Ветка: `master`.

Мод переведён с «подмены чужих руд» на **полностью самодостаточный**: каждый из **106** кусочков теперь имеет свой
генерируемый блок руды в 4 хостах (камень / дипслейт / незерак / эндстоун), генерируется во всех измерениях, настраивается
в конфиге и отключает чужую генерацию руд. Ниже — по каждому из 8 пунктов с фактами и ссылками на код.

Легенда: ✅ сделано · ⚠️ нюанс.

## 1. Каждый кусочек имеет свой блок руды — ✅

- Раньше блоки были только у 14 материалов. Сейчас блок есть у **всех 106** руд.
- Реализация: `BlockFortuneOre(OreHost host, int group)` хранит материал в метаданных (4 бита → 16 руд на блок).
  `group = ore.meta / 16`, метадата блока = `ore.meta % 16`. Регистрируется по одному блоку на группу и хост
  (`FortuneOres.preInit` → `host.registryName + "_g" + g`).
- Поиск блока для руды: `OreHost.blockFor(ore)`.

## 2. Под каждую текстуру кусочка создан блок руды — ✅

- Все 106 предметов-кусочков имеют текстуру и зарегистрированы; для каждого создан блок (пункт 1) и **4 текстуры блока**.
- Осиротевшая текстура `items/w.png` (без руды) — **удалена**.

## 3. XP при вскапывании и при плавке — ✅

- **Плавка:** `FortuneOres.addSmelting()` — опыт `ore.xpSmelt` для каждого кусочка (из `OreRarity`, у ванильных задан
  явно). Дополнительно зарегистрирована плавка самих блоков руды (шёлк) во всех 4 хостах.
- **Вскапывание:** `BlockFortuneOre.getExpDrop()` выдаёт случайный опыт в диапазоне `ore.xpDropMin..xpDropMax`
  (у universal — из рарности, у ванильных coal/diamond/redstone/lapis выставлены ванильные значения 0-2 / 3-7 / 1-5 / 2-5).
  Больше нет хардкод-таблицы на 14 позиций — опыт берётся из данных самой руды. ⚠️ Свои блоки не конфликтуют с
  `OreSwapper` (их дроп — предмет, а не ItemBlock, ветка свопа его не трогает; XP не дублируется).

## 4. Конфиг: вкл/выкл, высота, размер жил, измерение — ✅

Для **каждой** руды в её категории конфига (`Config.java`, категория = имя руды):

| Ключ | Смысл |
| --- | --- |
| `EnableRawOre` | вскопанная руда (наша/ванильная/чужая) даёт кусочек |
| `EnableOreGen` | генерация нашего блока + подавление такой же руды у всех остальных модов |
| `BaseDrop` / `BaseDropMax` | мин/макс кусочков за блок (до Fortune) |
| `SmeltCount` | сколько предметов даёт один кусочек в печке |
| `OreMinY` / `OreMaxY` | высота спавна |
| `OreVeinSize` | размер жилы (верхняя граница эллипсоида, как у ванилы) |
| `OreVeinsPerChunk` | число попыток жилы на чанк |
| `OreVeinChance` | шанс в % того, что попытка вообще что-то поставит — главный регулятор редкости |
| `OreHarvestLevel` | нужный уровень кирки: 0 дерево/золото, 1 камень, 2 железо, 3 алмаз |
| `SpawnInOverworld` / `SpawnInNether` / `SpawnInEnd` | измерения (по умолчанию все `true`) |
| `DimensionIds` | точный белый список id измерений; пусто — работают три переключателя выше |
| `NetherMinY` / `NetherMaxY` / `EndMinY` / `EndMaxY` | высота отдельно для Незера и Энда; `-1` — как `OreMinY`/`OreMaxY` |
| `Biomes` | биомы: `type:MOUNTAIN`, имя биома, `id:35`, префикс `!` — исключение; пусто — везде |

- Дефолты высоты/жил зависят от рарности (`OreRarity`: COMMON…EPIC), у ванильных — исторические значения.
- Разбор правил биомов — `BiomeFilter`; неизвестное правило пишется в лог и игнорируется, мир не ломается.
- ⚠️ Подавление чужой руды (`EnableOreGen`) **не** ограничено биомами: если сузить `Biomes`, руда становится реально
  дефицитнее, т.к. чужая версия убирается везде, а наша ставится только в разрешённых биомах.
- Размещение по измерениям **host-driven** (`WorldGenOres`): в каждой точке жилы ставится блок под реально
  присутствующую породу — камень/дипслейт (верхний мир и модовые каменные измерения), незерак (dim −1), эндстоун (dim 1).

## 5. Дипслейт-вариант + Et Futurum Requiem — ✅

- Хост `DEEPSLATE` (`OreHost`) резолвит блок дипслейта из конфига `DeepslateBlockId`
  (по умолчанию `etfuturum:deepslate`, поддерживается список кандидатов). Мода нет → дипслейт-вариант не ставится, краша нет.
- Генератор ставит дипслейт-вариант там, где реально стоит дипслейт (на «дипслейтовом уровне»).
- Дипслейт-вариант теперь есть у **всех 106** руд (текстуры `deepslate_ore_<stem>.png`).

## 6. Отключён спавн ванильных (и части модовых) руд — ✅ (с нюансом)

- `DisableAllOtherOreGeneration` по умолчанию **true** (`Config.java`): `OreGenSuppressor` отклоняет все жилы руд,
  идущие через `OreGenEvent.GenerateMinable` (ванильные + модовые CUSTOM).
- ⚠️ **Земля и гравий не трогаются** (`EventType.DIRT/GRAVEL`) — это рельеф, а не руда; их отключение продырявило бы
  ландшафт.
- ⚠️ Ограничения движка 1.7.10: ванильный **изумруд** размещается мимо этого события, поэтому его жилу отменить нельзя
  даже мастер-выключателем. Также вместе с рудами через это событие уходит **незер-кварц** (это тоже ванильная руда —
  соответствует «отключить любую ванильную руду»); вернуть всё чужое можно, выключив свитч в конфиге.
- `OreSwapper` остаётся в коде: если игрок выключит свитч и оставит чужие руды, подмена дропа в кусочки продолжит работать.

## 7. Созданы текстуры блоков (рисовать не требовалось) — ✅

- Создано **424** текстур блоков (106 × 4). 56 «ручных» текстур 14 базовых руд сохранены; остальные **368** —
  автоплейсхолдеры: арт кусочка наложен на сплошной фон соответствующего хоста (серый/тёмный/красный/светлый), без дыр.
- Заменяются на «настоящие» запуском `tools/build_textures.py` (наложение оверлея на 4 фона) — см. `tools/README.md`.

## 8. Перепроверка названий — ✅

- Все 106 руд: имя ↔ файл текстуры предмета ↔ строка локализации ↔ ключ имени блока — совпадают (проверено скриптом).
- Дубликатов имён нет. Категории конфига = имя руды. Единственный мусор (`items/w.png`) удалён.
- Имена блоков в `en_US.lang` сгенерированы для всех 106 × 4 (напр. `Deepslate Crimson Iron Ore`, `Nether Certus Quartz Ore`).
  `ru_RU.lang` не расширялся — недостающие ключи движок берёт из `en_US`.

- **Совместимость со старыми мирами намеренно нарушена** (registry-id блоков изменены на `fortuneOre_gN` и т.д.) — это

# Доработка 2026-08-18 — регистрация только включённого контента и теги сырой руды

Дата: 2026-08-18. Ветка: `main`. Компиляция: `./gradlew compileJava` — проходит (EXIT 0), `spotlessApply` применён.

## 1. Отключённое не регистрируется — ✅

Раньше мод регистрировал всё независимо от конфига: 28 блоков руды (7 групп × 4 хоста), 448 иконок блоков
(28 × 16 мет) и 112 иконок кусочков — даже если игрок оставил 34 руды из 112.

Теперь регистрация идёт строго по конфигу:

- **Кусочек (сырая руда).** `Ore#enabled` (`EnableRawOre || EnableOreGen`) решает всё: у выключенной руды нет имени,
  нет иконки на атласе, нет записи в ore dictionary, нет рецепта плавки и рецептов в машинах, и её нет в креативной
  вкладке и NEI (`ItemChunk`, `FortuneOres#registerChunkOreDict`, `addSmelting`, `MachineCompat`).
- **Блок руды.** `Ore#usesHost(host)` — новый метод, который сводит `EnableOreGen` и `SpawnInOverworld/Nether/End`
  (или `DimensionIds`) к вопросу «нужен ли этой руде блок такого хоста». `FortuneOres#registerOreBlocks` регистрирует
  блок хоста и группы, только если хотя бы одна включённая руда в этой группе генерируется в измерении этого хоста.
  Выключили генерацию в Незере у всех руд — незерак-блоки не регистрируются вообще; то же для эндстоуна и
  камня/дипслейта.
- **Дипслейт-хост** регистрируется, только если установлен мод, чей id совпадает с доменом `DeepslateBlockId`
  (проверка по списку модов `Loader`, потому что реестр блоков в pre-init ещё не заполнен). Нет Et Futurum Requiem —
  нет 7 блоков и их иконок.
- **Иконки блоков** регистрируются только для тех мет, которые хост реально несёт; остальные показывают текстуру
  породы хоста (`stone` / `netherrack` / `end_stone`) — это нужно для блоков, оставшихся в старых мирах.
- **Все руды выключены** — мод не регистрирует ни предмет, ни блоки, ни креативную вкладку; `init`/`postInit`
  выходят сразу.

Что это даёт на дефолтном конфиге (34 руды из 112 включены):

| | было | стало (все измерения + дипслейт) | стало (только Оверворлд, без дипслейта) |
| --- | --- | --- | --- |
| Блоков в реестре | 28 | 24 | 6 |
| Иконок блоков | 448 | 136 | 34 |
| Иконок предметов | 112 | 34 | 34 |

(24, а не 28 — группа 3 целиком состоит из выключенных по умолчанию руд.)

**Важно:** незарегистрированный блок не читается и из сохранения. Отключение руды или измерения в уже сгенерированном
мире удаляет оттуда соответствующие блоки руды — ровно как удаление мода. Это записано в подсказках конфига.

## 2. Теги сырой руды — ✅

- Регистрация кусочка в ore dictionary стала **безусловной**. Раньше кусочек получал имя `oreX` только если это имя
  уже занял кто-то другой (`matched`) — то есть у руды, которую генерирует сам мод и которой нет в паке, сырая руда
  оставалась вообще без тега и её не видела ни одна машина, ни один рецепт, ни один сканер.
- Регистрация переехала из `init` в `preInit`: мод, чей `init` выполняется раньше нашего, теперь тоже видит кусочки.
- Одна точка входа — `FortuneOres#registerChunkOreDict` (идемпотентна, флаг `Ore#oreDicted`). Класс `OreDictHandler`
  (слушатель `OreRegisterEvent`, дублировавший эту логику) удалён: ждать чужих регистраций больше незачем.
- Регистрируются **все** имена руды, включая алиасы (`oreAluminum` + `oreAluminium`, `oreMithril` + `oreMythril`,
  `oreSaltpeter` + `oreSaltpetre`), так что кусочек подходит под любое написание, которое ждёт чужой мод.
- Исправлен режим `AllowProcessing = false`: раньше `init` всё равно регистрировал кусочек как `ore*`, а обработчик
  события — ещё и как `dust*` (двойная регистрация и потенциальный дюп в машинах). Теперь префикс один: `ore*` или
  `dust*`.
- Исправлено получение имени материала: вместо `replace("ore", "")` (что калечило имена, внутри которых встречается
  «ore») срезается только префикс. Имена `oreNether*` и `oreDense*` кусочку не выдаются — они означают «та же руда,
  но с двойной отдачей».
- Добавлена самопроверка `FortuneOres#verifyChunkOreDict`: после регистрации мод перечитывает ore dictionary и пишет в
  лог `severe`, если у включённой руды нет какого-то из её тегов, плюс итоговую строку
  «N ore chunks registered under M 'ore*' names».
- Проверен весь каталог: у всех 112 руд есть имя ore dictionary, иконка кусочка, 4 текстуры блоков и строки
  локализации en_US. Единственное пересечение имён — `oreTitanium` у Titanium и Rutile, и оно намеренное
  (`OreSwapper` отдаёт приоритет владельцу имени над алиасом).

# Доработка 2026-08-18 (2) — все руды как сырьё, генерация выключена, гейт по материалу, полный ru перевод

Дата: 2026-08-18. Ветка: `main`. Сборка: `./gradlew build` — проходит.

## 1. Новые дефолты конфига — ✅

- `EnableRawOre` = **true** у всех 112 руд: ломая любую руду любого мода, игрок получает кусочек этого мода.
- `EnableOreGen` = **false** у всех: мод ничего не генерирует и ничего не подавляет, пока игрок не включит руду вручную.
- Списки `DEFAULT_REPLACE` / `DEFAULT_RAW_ONLY` из `Config` удалены — дефолт теперь одинаковый для всех руд.

Следствие для регистрации: в дефолтной конфигурации **не регистрируется ни одного блока руды** (блоки нужны только
при включённой генерации), то есть атлас блоков не тратится вообще.

## 2. Гейт по материалу — ✅

Руда, для материала которой в паке ничего не зарегистрировано, выпадает из игры целиком, даже будучи включённой.

- Критерий — `FortuneOres#hasMaterial`: ванильная руда проходит всегда, остальные проходят, только если кусочек во
  что-то превращается (явная цель плавки руды, `ingot*`, `gem*` или `dust*` в ore dictionary). Это тот же вопрос, на
  который отвечает `resolveSmeltResult`: кусочек, который не во что сплавить — тупик, а подменять им дроп чужой руды
  значит ломать тот мод.
- Когда считается: `resolveMaterials()` в `init` (ore dictionary заполняется в pre-init всех модов) и повторно в
  `postInit` — для модов, регистрирующих слитки и самоцветы поздно. Материал не может «пропасть», поэтому второй
  проход только добавляет; для догнавших руд повторно вызываются `addOreDicting`/`addBlockOreDicting`.
- Что отключается у такой руды: имя кусочка, иконка кусочка, запись в ore dictionary, рецепт плавки, рецепты в
  машинах, показ в креативе/NEI, подмена дропа чужой руды, генерация своего блока и подавление чужой генерации.
  Иконки регистрируются при стичинге атласа — то есть уже после `postInit`, поэтому гейт успевает на них повлиять.
- Тумблер `RequireRegisteredMaterial` (AAAGeneral, по умолчанию `true`) выключает правило целиком.
- В лог выводится итог: сколько руд активно, сколько выключено конфигом, сколько отброшено из-за отсутствия
  материала, и поимённо — какие именно отброшены.

Чего гейт **не** может: сам предмет-кусочек (один на все 112 руд) и блок-контейнер группы регистрируются в
`preInit`, когда ore dictionary ещё пуст. Предмет один, а блоки при дефолте не создаются вовсе; если игрок включит
генерацию руды, материала для которой нет, будет зарегистрирован пустой блок группы (1 объект на 16 руд) — без
иконок, дропа и генерации.

Порядок регистрации ore dictionary вернулся из `preInit` в `init`: узнать про материалы раньше невозможно.

## 1. Текстуры кусочков руд перерисованы — ✅

Перерисовано **88 из 113** текстур кусочков. Не тронуты те, что и так читались хорошо: медь, железо, золото,
уже огранённые самоцветы (diamond, emerald, ruby, sapphire, amethyst, aquamarine, apatite, cinnabar, draconium,
оба certus quartz, benitoite оставлен в списке перерисованных), redstone, lapis, astral_starmetal, ardite,
bauxite, arcane_crystal, crystal, platinum, abyssalnite, adamantium и `fallback`.

### Что было не так

Худшие текстуры — плоские кружки и бесформенные кляксы без объёма (`coralium_pearl`, `tanzanite`, `malachite`,
`shadow`, `carmot`, `boron`, `magnesium`, `neridium`, `infuscolium`, `kalendrite`, `onyx`, `thorium`, `titanium`,
`rutile`, `potash`, `fossil`, `cheese` и ещё десятки), плюс целые семейства одинаковых силуэтов: шесть
`infused_*` отличались только цветом, четыре «серых камешка» (aluminum / silver / silicon / lithium) были одной
формы, `dark` и `coal` почти не читались на тёмном фоне.

### Как сделано

Стиль — JAPPA (современные ванильные предметы): врезанный тёмный контур, 6-ступенчатая рампа со сдвигом оттенка
(тени уходят в синий и насыщаются, блики — в жёлтый и обесцвечиваются), свет сверху-слева, точечный блик,
мягкий дизеринг вместо полос.

Главное требование — **у каждой руды свой силуэт**. Форма выбрана так, чтобы она сама называла материал:

| Семейство | Форма | Примеры |
| --- | --- | --- |
| Самоцветы | **своя огранка на камень** | zanite — круглый бриллиант, benitoite — изумрудная (ступенчатая), peridot — маркиза, topaz — груша, tanzanite — триллион, anglesite — багет, neridium — кушон, onyx — октагон, amber — капля |
| Кристаллы | друзы, призмы, иглы | quartz — гексагональная призма, alduorite и mithril — друзы, silver — дендрит, dilithium — сросток |
| Металлы | самородки, слитки, пластины, стружка | aluminum — стопка фольги, iridium — сложенный лист, cobalt — шипастый сросток, pyrite — кубы (пирит и правда кубический) |
| Порода и соли | насыпи, крупа, слоистые сколы | lithium и saltpeter — насыпи порошка, boron — соляные крупинки, biotite — слюдяные листы, thorium — жила в породе |
| Органика | предметные силуэты | fossil — ребристая раковина, cheese — ломоть с дырками, lemurite — кость, viroxores — пузырьки, coralium — веточка коралла |
| Светящееся | свой ореол плюс акцентный цвет | uranium — жеода со светящимися вкраплениями, starsteel — угли, solar — солнечный диск, ignatius и vulcanite — огонь и капля лавы |
| Таумкрафт | одна форма на аспект | air — завиток, fire — пламя, water — капля, earth — валун с трещинами, order — симметричная октаграмма, entropy — расколотые осколки |

Итого **77 силуэтов**, 88 вариантов (11 — зеркальные отражения, что даёт паре родственных материалов разный
контур без второй ручной формы). Проверка уникальности встроена в генератор: `render.py` печатает предупреждение,
если два кусочка получили один и тот же силуэт (сейчас — «every ore has a silhouette of its own»).

### Генератор

Новый инструмент `tools/chunk_art/`:

- `forms.py` — библиотека силуэтов, каждый 16×16 ASCII (`#` тело, `-` внутреннее ребро огранки, `o` порода,
  `*` акцент, `^` `+` `,` — принудительный блик, свет, тень). Проверяет размеры и дубли имён при импорте.
- `palette.py` — таблица «имя файла → (форма, базовый цвет, стиль, акцент)». Стиль (`metal`, `gem`, `crystal`,
  `rock`, `organic`, `glow`) меняет рампу и освещение, но не форму.
- `render.py` — рендер. Контур вычисляется из силуэта, а не рисуется руками, поэтому тонкие детали в 1–2 пикселя
  не превращаются в чёрную палку, а остаются в теневых тонах.

Запуск: `python tools/chunk_art/render.py --sheet` (флаг дополнительно кладёт контактный лист для просмотра).

Текстуры **блоков** руды не трогали — они собираются отдельно из `tools/texture_input/overlays`.

## 2. Поддержка Tinkers Construct и техномодов — ✅

### 2.1 Плавильня Tinkers Construct — новый `TinkersCompat.java`

Проблема была та же, что и с дробилками: Tinkers заводит плавку только для своего жёстко зашитого списка
материалов, поэтому кусочек любой руды за пределами iron / gold / copper / tin **вообще не был входом плавильни**.

Теперь для каждой активной руды регистрируется плавка кусочка и всех четырёх вариантов блока руды
(камень, дипслейт, незерак, эндстоун):

- **Жидкость** ищется в форджевом `FluidRegistry` по всем соглашениям 1.7.10 — `<материал>.molten` (сам Tinkers),
  `molten.<материал>` (GregTech и те, кто скопировал), `molten<материал>`, `<материал>.liquid`, голое имя.
  Перебираются все имена руды, включая алиасы, поэтому `Aluminum` находит и `aluminium.molten`, а Rutile
  сваливается в расплавленный титан ровно так же, как его кусочек плавится в титановый слиток.
- **Температура** берётся из собственной таблицы `FluidType` Tinkers (читается рефлексией), а не выдумывается:
  расплав железа из кусочка плавится при той же температуре, что и любое другое железо. Если таблицы нет —
  форджевая температура жидкости, иначе 600.
- **Количество**: кусочек = `MachineOutputMultiplier` слитков жидкости (по умолчанию 2 — стандартное удвоение
  руды), блок руды = это же, умноженное на `BaseDrop`. То есть переплавить блок никогда не выгоднее, чем добыть
  его и переплавить кусочки — у тех ещё и Fortune сверху.
- Вход, который Tinkers уже плавит, **не перезаписывается** (`getSmelteryResult` спрашивается заранее), так что
  собственный баланс мода не ломается.
- Всё через рефлексию и `Loader.isModLoaded`, метод плавки ищется **по форме сигнатуры**, а не по точному
  совпадению — форк или другая сборка Tinkers всё равно получит рецепты, а не стектрейс.
- Материалы без расплава (большинство самоцветов) просто пропускаются — это не ошибка, кусочек остаётся печным.

### 2.2 Thaumcraft — новый `ThaumcraftCompat.java`

Thaumcraft выводит аспекты предмета из его рецепта крафта, а у кусочка руды рецепта нет — он выпадает из мира.
Поэтому кусочки были **полностью без аспектов**: их нельзя было ни сканировать, ни положить в тигель, ни потратить
на инфузию, хотя тот же материал из руды самого Thaumcraft всё это умеет.

Теперь кусочку и блоку руды назначаются аспекты того, во что кусочек плавится (спрашивается у
`ThaumcraftCraftingManager.getObjectTags`), плюс `terra` за породу. Если Thaumcraft материал не знает — запасной
вариант: `metallum` для металла (в паке есть `ingot*`) или `vitreus` для самоцвета. Блок руды стоит столько же,
сколько кусочки, которые он бы уронил.

### 2.3 Что уже работало и почему этого мало

Mekanism, Thermal Expansion, IC2 и Immersive Engineering закрыты `MachineCompat` (Enrichment Chamber, Pulverizer,
Macerator, Crusher) — без изменений. GregTech и всё, что читает **имена** ore dictionary, получает совместимость
даром: кусочки зарегистрированы как `ore*` (или `dust*` при выключенном `AllowProcessing`), блоки руды — тоже,
плюс `oreDeepslate*` для дипслейт-варианта.

### 2.4 Новые настройки конфига (секция `AAAGeneral`)

| Ключ | По умолчанию | Что делает |
| --- | --- | --- |
| `TinkersSmelteryIntegration` | `true` | Плавка кусочков и блоков руды в плавильне Tinkers |
| `ThaumcraftAspectIntegration` | `true` | Аспекты Thaumcraft для кусочков и блоков руды |
| `OreDictionaryTooltips` | `false` | Показывать имена ore dictionary в расширенной подсказке (F3+H) |

## На что обратить внимание

- **Подсказка ore dictionary теперь по умолчанию выключена.** Это единственное изменение видимого поведения,
  не связанное с текстурами. Вернуть — `OreDictionaryTooltips=true`.
- Интеграции с Tinkers и Thaumcraft **не проверены в живом клиенте** — в дев-окружении этих модов нет. Весь код
  рефлексивный, обёрнут в `try/catch` и молча выключается, если API не нашлось, так что худший исход — строка в
  логе и отсутствие рецептов, а не падение. Проверить стоит на паке, где эти моды есть: в логе должны появиться
  строки `Tinkers' Construct smeltery: N melting recipes ...` и `Thaumcraft: aspects registered for N ore chunks ...`.
- Текстуры блоков руды остались прежними. У пары материалов кусочек сменил оттенок (malachite стал зелёным, как
  настоящий малахит, а не бирюзовым) — блоки при этом уже были в правильном цвете, но если захочется идеального
  совпадения, перерисовывать надо оверлеи в `tools/texture_input/overlays`.
